# Recovering interrupted schedule preparation

Use `python checked_prepare.py --cases CASE ...` for preparation or recovery. The wrapper binds each case's checkpoints to the SHA256 hashes of the original exact design and input state, the reviewed archive for prospective inputs, all scientific optimizer/preparation sources, and the wrapper itself **before starting a new search**. A mismatch raises an exception. Each accepted search sweep is an atomic checkpoint; a completed search additionally records hashes of all checkpoints and the design.

Twelve smaller cases completed in the initial crash-recovery session before this wrapper was added. They were bound once using `--adopt-current-checkpoints`, after checking the completed design's exact input and scientific-source hashes and requiring that every existing search checkpoint was complete. The eight development cases additionally reproduced all three archived optimized schedules exactly. The adoption is recorded explicitly in each sidecar and must not be used as a generic bypass for stale or unfinished checkpoints. The two NH3 cases were bound before any search began.

The low-level `run.py prepare` and `optimize.search` are implementation routines. They are not the supported entry points for interrupted runs. The wrapper adds provenance protection without modifying the scientific sources already recorded in the first twelve frozen designs. Run `python execute.py freeze` only after all cases have completed, then `python execute.py run` and `python execute.py finish`. This execution wrapper additionally binds the recovery sidecars, completed-checkpoint hashes, oracle evidence, execution-wrapper hashes, and all-schedules manifest. It checks the exact external input design/state provenance again before each propagation; changed states or targets are rejected. The underlying runner checks frozen scientific-source and design hashes again.
