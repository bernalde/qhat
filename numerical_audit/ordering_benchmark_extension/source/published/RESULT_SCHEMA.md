# Published comparator artifact schema

The source definitions are in `PROTOCOL.md`; runtime boundaries are in `timing_scope.json`. Run `python run.py prepare extra`, `python run.py freeze extra`, `python run.py run extra`, and `python run.py collect extra` in order. The `v2` campaign uses the same actions, after compiling `v2_exact.cpp`. `finish_v2.py` waits for all complete V2 designs, then freezes, checks uniform scaling, propagates and collects. Set `QHAT_ROOT` to the reviewed QHAT checkout when relocating the artifact. The selected directory must be named `qhat`, because the frozen helper imports that package from its parent; the replay launcher must verify that all imported QHAT modules resolve under the selected archived directory before running. An arbitrary directory basename is not supported by this frozen helper.

Each campaign stores `designs/{case}.json`. The base fields are copied from the immutable input and include exact coefficient numerator strings, one positive common denominator, orbital/electron counts, the affine basis and input hashes. `methods` maps method labels to:

- `schedule`: chronological `[word, integer_numerator]` pairs; `word` is a list of `[qubit_index, Pauli_letter]` pairs. The physical coefficient is numerator divided by the design denominator. Duplicate words are permitted in literal parent schedules.
- `formula_order`: 1 or 2. For 2 the stored list is the forward chronological half of a symmetric formula, not the complete repeated pulse sequence.
- `schedule_sha256`: canonical JSON hash of the encoded schedule, using the shared helper's sorted-key compact serialization.
- `metadata`: the published prescription, explicit completion/adaptation, deterministic tie choices, partition/search details and descriptive timings.

V2 `metadata.eq4_order` uses indices into the dense-IXYZ-sorted coefficient list. The physical schedule reverses this order. Each `history` row is `[incoming_dense_index, chosen_insertion_position, exact_integer_l1]`. The final column is the coefficient-l1 norm of the incremental **W polynomial in numerator arithmetic**, with W the triple-commutator polynomial displayed in the manuscript. Divide by `24 * denominator**3` to obtain the coefficient-l1 norm of the normalized incremental V2 coefficient; the common step-size-squared factor is omitted during selection. This positive common factor cannot alter a chosen position. `accepted.tsv` records the same accepted insertion history, one fsynced line per term. It is not a log of circuit errors.

`metadata.exact_uniform_scaling_reuse` identifies an order inherited from an exactly positive-scaled target. Its `integer_multiplier` acts on numerator integers; account separately for the denominator when interpreting physical coefficient scaling. V2 history values scale cubically; Tomesh path numerator diagnostics scale quadratically. `check_scaling.py` validates both and verifies the physical coefficient ratio is exactly 5/4.

`freeze.json` records all fourteen design hashes and producer-source hashes before propagation. Every result is `results/{case}.{method}.b{budget_units}.json`, with a corresponding compressed `actual` state array. The raw row records the available rotation budget, feasible step count, actual emitted count, metric values, plan/schedule/state hashes and timing. An infeasible row has no state. The comparison retains the full Pauli-invariant affine closure; no particle-number projection or renormalization within a symmetry sector is used.

For first order, `steps=floor(U*b/R)` and the cost is `steps*R`. Here U is the consolidated target word count and R is the emitted schedule length. For the native V2 Strang schedule R=U, `steps=floor((U*b-1)/(2*(U-1)))` and the physically merged count is `2*steps*(U-1)+1`. A zero step count is infeasible. A first-order and a Strang method share the same V2-selected order but have distinct propagation rows and costs.

`results.json` collects every raw row after all case completion files exist. `published_comparison_summary.json` is a secondary descriptive comparison against the already archived conserving candidate; use the newly independently checked candidate rows for final manuscript reporting. No row error is read by ordering preparation.
