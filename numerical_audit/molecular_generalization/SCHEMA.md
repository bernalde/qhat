# Molecular generalization: scientific wire contract

This is a new study adapter. Existing frozen producers and numerical kernels remain unchanged. No prospective physical errors may be measured until the old-case end-to-end preflight, numeric annealing calibration and full protocol/source/environment freeze pass.

`REGISTRY.json` fixes the two primary families, exact geometries and active spaces before new errors. `PROTOCOL.json` is currently old-preflight development with main execution disabled. Main uses two repetitions; preflight uses one old LiH repetition. Each case/repetition has these nine constructor identities: parent/0, canonical/0, magnitude/0, full/32, full/64, window/32, window/64, annealing/32, annealing/64. Zero is an identity tag for parent/cheap controls, never a claim that their measured cost is zero. Constructor JSON orders use original zero-based unit labels.

The unchanged exact model TOML convention has case,n,electrons,partition=conserving,denominator as a decimal integer string,source_json_sha256,baseline_order and [[units]] with words and exact integer numerators. Model TOML labels are one based. Fixed HF is low `electrons` bits set; every physical method uses that same state. New case n/electrons must equal the frozen case specification, n<=14, and binomial(n,electrons)<=2000. Full physical propagation has2^n amplitudes; the unchanged exact-H reference uses the checked fixed-N sector, not a smaller spin projection. Main primaries are12m/8e (fixed-N495); old preflight is14m/4e (1001).

## Candidate TOML for physical and objective adapters

Header: version=1, order_index_base=1, case, n, electrons, partition=conserving, input_sha256 (modelTOML), source_json_sha256, protocol_sha256, source_freeze_sha256, mode (main/preflight), repetitions (2/1), expected_logical_rows (72/36 per case), training_time=1.0, training_budget_multiplier=30, times=[0.65,1.35], rotation_cap_multipliers=[8,24]. Expected identities must be derived independently from these fixed declared grids and mode, not merely accepted from the expected-count field.

Each [[candidates]] row has name,order_id,arm,repetition,cpu_budget,partition,formula=2,time,budget_multiplier,order,constructor_sha256,claimed_score,score_kind=diagonal_reference_cubic_response,eligible (Boolean). `order` is a complete ONE-based original-label permutation in this boundary. `constructor_score` can be a checked equal alias of claimed_score. Parent and optimized rows also have parent_sha256; parent self-references its constructor digest, optimized arms reference the common measured parent. Cheap rows omit parent_sha256: they have no shared parent prefix. Names/order_ids are unique bounded ASCII labels. One order_id identifies exactly one frozen constructor, repeated over the four physical conditions. A valid scored parent fallback may have eligible=false with explicit constructor failure retained; no failed method is represented as a successful search. An unscored/missing parent cannot pass complete panel admission; retain a clear refusal/incomplete artifact instead of silently losing rows.

A physical adapter accepts an exact modelTOML plus candidateTOML and a fresh output directory. It emits TOML report plus little-endian complex128 state binaries, complete source/model/order/candidate hashes and all logical row identities. Exact circuit deduplication may share computation but every logical observation and constructor cost remains represented. Include norms/leakage, raw normalized-overlap deficit, ratio floors, failures and admission reasons. Save every case/time exact reference state with its sector/coupling/Hermiticity checks. Candidate eligibility follows into results and primary decisions.

Independent replay must read original model/Pauli data and unfused full-register circuits through the unchanged independent numerical entrypoints, check every distinct exact circuit and every logical row/reference join, and retain failures rather than reporting a partial panel complete. Objective replay checks every selected or persisted raw proposed-best score, using the unchanged archived ResponseCore and native SparseResponse as separate references. Include a scored-witness manifest for non-selected raw candidates if necessary; do not drop them because a native promotion decision retained the parent. Method-specific roster logic belongs in these new wrappers, not edits to old physical/independent/objective producers.

Main inventory across two cases:4parents+24optimized+8cheap=36constructor records; all four physical conditions give144logicalrows. One old preflight case/repetition has9records/36rows. Cheap methods have separate complete-cost constructor receipts in each repetition. Actual versus attributed optimized parent costs are recorded separately; physical conditions never multiply construction cost. Primary questions are window-minus-full and annealing-minus-full at64CPU/T1.35/8U, using the frozen case-level/two-repetition ambiguity rule. Everything else, including parent and cheap quality, is context.

## Artifact and proposed-score bindings

Headers also supply protocol_path=source_snapshot/numerical_audit/molecular_generalization/PROTOCOL.json, source_freeze_path=INPUT_PROTOCOL_FROZEN.json and [[constructor_artifacts]] entries(order_id,path,sha256). All paths are canonical relative under DATA, without traversal/symlink escape. DATA layout is inputs/{case}/model.toml, model.json; constructors/{case}.rep{rep}.{arm}.B{B}.json; panels/{case}.toml. Adapters may derive DATA from the fixed inputs/case/model.toml layout or accept an explicit data-root argument. Actual-byte hashes are rebound by Julia; the independently implemented Python panel consumer also validates every canonical JSON semantic relationship. No new general-purpose JSON parser is required in Julia. Missing optional byte-binding paths cannot certify full scientific admission.

Final constructor JSON has TOPLEVEL case,arm,repetition,cpu_budget,n,electrons,model_json_sha256,model_toml_sha256,protocol_sha256,source_freeze_sha256,order(zero-based),score,cubic_response,steps,score_kind,eligible,costs. Raw backend data lives separately in result. Optimized records reference the measured parent_sha256; parent and cheap JSON have no external parent and omit/null that field. Parent self-reference occurs only in the candidate TOML, after its constructor-file digest exists, avoiding a JSON self-hash cycle.

The objective CLI accepts optional fourth WITNESSES.toml. It repeats exact case/model/protocol/source/grid headers, expected_witnesses and witness_inventory_complete=true. Each [[witnesses]] record identifies name,order_id,constructor_sha256,arm/repetition/cpu_budget,one-basedorder,claimed_score,score_kind,role=raw_proposed_best,selected Boolean,and native_score or explicit native_refusal. Parent hashes are present only when real. This covers persisted unpromoted window/annealing score claims. Empty witnesses is legal only when the independent Python consumer confirms no raw proposed-best claim exists. Omitting a witness manifest may permit selected-row diagnostics but cannot mark full objective coverage complete. Native-refused or floor-censored claims remain explicit incomplete/censored, not verified success.
